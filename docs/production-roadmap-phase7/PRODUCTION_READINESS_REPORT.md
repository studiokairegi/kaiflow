# Production readiness report

**Date:** 14 November 2026. **Scope:** KairFlow Intelligence, after Phases 1 to 7 of the Seven-Phase roadmap.

## 1. Verdict

# NOT READY for production workloads.

The code, tests and operating documents are in good shape **as far as an offline sandbox can show**. But in every phase since Phase 2 the *live* gates were
never met, because no phase could reach a network, a database, a mail provider or a Gemini key. Phase 7 is the phase that was meant to close them, and it could not either.
So this report separates what is established from what is only asserted by mocked tests:

- **Ready to start now (owner actions only):** Stage 0 of `PRODUCTION_ROLLOUT_PLAN.md`.
- **Ready after a rehearsal on a copy:** Stage 1 (three additive, reversible migrations).
- **Not ready, and not claimable from here:** Stages 2 to 6. Each needs a live system. **Stage 5, the first one that can send email, needs your written approval and is not
  recommended until Stages 3 and 4 have produced real evidence.**

**Outbound sending remains disabled.** Nothing in Phase 7 changed a send, approval, suppression, kill-switch or provider-gate code path. The one change that touches permissions
(`20270105090000`) makes two functions *less* reachable, not more.

## 6. Metrics: what can be measured, and how

| Roadmap metric | Source | Honest limit |
|---|---|---|
| Successful vs failed jobs | query 1 | counts by kind and state |
| Job processing time | query 2 | p50/p95/max from `result._run.duration_ms` on successful jobs |
| Gemini usage and fallback frequency | queries 3 and 14 | request counts per provider; fallback share |
| AI cost | query 3 | **request counts only**; the free tier has no billing, so there is no money figure |
| Prospect quality, research accuracy | query 9b sample, labelled by you | needs a human; see below |
| Duplicate rate | queries 8 and 8b | shared domains, which include legitimate multi-game developers |
| Draft quality | Stage 4 review | needs a human |
| Inbound classification accuracy | query 12b sample, labelled by you | needs a human |
| Follow-up completion | query 13 | follow-up drafts by step and state |
| Worker recovery time | queries 4 and 15 | **not measured directly**: heartbeat keeps only the latest row; stuck leases show recovery indirectly |
| Safety state | queries 11, 16, 17, 17b, 19, 20 | each should show the safe answer in the plan |

**How to label a sample, and how far to trust it.** For each sampled row, open the sources and record yes/no for each question in the plan (identity correct, no invented facts,
qualification fair). With 20 items the answer is coarse: **18 of 20 correct is "about 90%", but the plausible range is roughly 70% to 97%** (95% Wilson interval);
**20 of 20 only rules out being below about 84%**; 16 of 20 spans about 58% to 92%. So the gates in the plan are screening gates: they catch a clearly bad system, not a precisely good one. Zero-tolerance rules
(any invented contact, any draft breaking a business rule, any sent row in shadow mode) are stated as zero precisely because a small sample cannot show a rare failure is absent. If you want a tighter
estimate, label 40 (36 of 40 gives about 77% to 96%) or 80 (72 of 80 gives about 82% to 95%).
